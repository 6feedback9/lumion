Швидкість сайту і Core Web Vitals: що перевірити і як пришвидшити у 2026

Повільний сайт втрачає клієнтів ще до того, як вони його побачили. Розбираємо метрики Google і прості кроки, що їх покращують.

Три метрики Core Web Vitals

  • LCP (швидкість завантаження основного вмісту): добре — до 2,5 с
  • INP (швидкість реакції на дії користувача): добре — до 200 мс
  • CLS (стабільність макета, без «стрибків»): добре — до 0,1

Це порогові значення, які Google вважає «хорошими». Їх видно у Search Console (Core Web Vitals) та в PageSpeed Insights.

Як перевірити

Введіть адресу в PageSpeed Insights і подивіться окремо мобільну версію: саме вона зазвичай слабша. Звертайте увагу на дані реальних користувачів, якщо вони доступні, а не лише на «оцінку».

8 способів пришвидшити сайт

  • Стисніть зображення і використовуйте сучасні формати (WebP/AVIF)
  • Додайте ліниве завантаження (loading="lazy") для зображень нижче першого екрана
  • Задайте розміри зображень, щоб макет не «стрибав»
  • Підключайте лише потрібні шрифти й вагові варіанти
  • Приберіть або відкладіть непотрібні скрипти (чати, віджети, піксельні коди)
  • Мінімізуйте CSS та JavaScript
  • Увімкніть кешування та CDN
  • Оберіть швидкий хостинг і платформу

Чому це впливає на SEO і продажі

Core Web Vitals — один із сигналів сторінкового досвіду в Google, але важливіший прямий ефект: що довше завантажується сторінка, то більше людей іде. Для інтернет-магазину кожна секунда затримки — це втрачені замовлення. Це частина технічного SEO, яку варто перевірити одразу.

Часті запитання

Яка швидкість сайту вважається хорошою?

Google вважає хорошими LCP до 2,5 с, INP до 200 мс і CLS до 0,1.

Чи впливає швидкість сайту на позиції в Google?

Так, як один із сигналів сторінкового досвіду, а також через поведінку користувачів: повільні сторінки частіше закривають.

Що найчастіше сповільнює сайт?

Важкі зображення, зайві скрипти, шрифти й слабкий хостинг.
